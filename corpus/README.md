# Корпус переговорных диалогов

Корпус строится из сессий Negotiation Arena и предназначен для оценки
классификаторов, обучения модели намерений и сравнения формулировок оппонента.
Формат версии `1.0` описан в `schema-v1.json`.

## Что входит в запись

Одна строка JSONL содержит один диалог:

- полный снимок сценария со скрытой целью и правилами;
- начальную реплику оппонента;
- пары реплик игрока и оппонента;
- намерение, технику, источник классификации и источник ответа;
- изменения доверия, аргументации и давления;
- ошибки, риски, сильные стороны и рекомендацию;
- состояние и показатели до и после каждого хода;
- итог сессии, если она завершена;
- связь с родительским диалогом для веток повторной проработки.

`quality.complete` показывает, что у каждого хода есть разметка и оба снимка
состояния. Старые записи до появления контрольных точек тоже экспортируются, но
получают `quality.complete: false` и список причин в `quality.issues`.

`playerId` и имя игрока не экспортируются. `dialogueId` является случайным ID
сессии и нужен для дедупликации и связи веток.
Поле `origin` различает реальные runtime-сессии и синтетические эталонные
диалоги.

## Экспорт

Экспорт требует административный Bearer token:

```powershell
New-Item -ItemType Directory -Force corpus/exports | Out-Null
curl.exe -sS `
  -H "Authorization: Bearer $env:ARENA_ADMIN_TOKEN" `
  "http://localhost:8080/api/v1/admin/corpus?status=finished&format=jsonl&limit=100" `
  -o corpus/exports/finished.jsonl
```

Поддерживаются фильтры `status`, `scenarioId`, `limit` и `offset`. Формат
`format=json` возвращает страницу с метаданными; `format=jsonl` возвращает одну
запись на строку. Для большой базы следует последовательно увеличивать
`offset`. Экспорты исключены из Git, потому что могут содержать пользовательский
текст.

## Разделение данных

Ветки одного исходного диалога нельзя распределять между train и test. Сначала
объедините записи по `parentDialogueId`/`dialogueId`, затем разделяйте группы.
Для первой модели рекомендуются доли 70/15/15 и стратификация по сценарию,
сложности, намерению и исходу.

Перед обучением следует исключить пустые диалоги, записи с
`interpretationSource: "unknown"`, технические проверки и явные персональные
данные в свободном тексте. Исходные экспорты лучше сохранять неизменными, а
очистку выполнять отдельным воспроизводимым скриптом.

Базовая подготовка без внешних Python-зависимостей:

```powershell
python scripts/prepare_corpus.py `
  corpus/exports/local-corpus-v1.jsonl `
  corpus/exports/prepared-v1
```

Скрипт по умолчанию оставляет только `quality.complete: true`, удаляет дубликаты,
исключает диалоги без ходов,
не допускает `playerId`, удерживает родительский диалог и все его ветки в одной
выборке и создаёт `train.jsonl`, `validation.jsonl`, `test.jsonl` и
`manifest.json`. Если независимых корневых диалогов достаточно, все выборки с
ненулевой долей будут заполнены. Манифест содержит распределение по сценариям,
намерениям, исходам, источникам ответов и происхождению записей. Для отдельного анализа старых записей доступен флаг
`--include-incomplete`.

Синтетический стартовый набор для проверки пайплайна воспроизводится движком:

```powershell
Set-Location backend
go run ./cmd/corpus-seed -output ../corpus/seed-v1.jsonl
```

Текущая версия `seed-v1.jsonl` содержит 12 диалогов и 99 ходов по трём штатным
сценариям. Она нужна для проверки формата, разбиения и метрик качества. Для
обучения модели её следует дополнять полными runtime-диалогами.
