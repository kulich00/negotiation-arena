# Конфигурация

Backend читает настройки из переменных окружения при запуске. Сам сервер не
загружает `.env`; Docker Compose передаёт его через `env_file`.

## Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `APP_ENV` | `development` | Режим приложения. Значение `production` включает обязательную проверку БД и пароля администратора. |
| `HTTP_ADDR` | `:8080` | Адрес прослушивания HTTP-сервера. |
| `DATABASE_URL` | пусто | PostgreSQL DSN. При пустом значении используется непостоянное in-memory хранилище. |
| `ADMIN_EMAIL` | `admin@example.com` | Логин администратора, создаваемый или обновляемый при запуске. |
| `ADMIN_PASSWORD` | `change-me` | Пароль администратора. В БД сохраняется bcrypt hash. |
| `ADMIN_SESSION_TTL` | `12h` | Время жизни административного Bearer token. |
| `ADMIN_LOGIN_MAX_ATTEMPTS` | `5` | Число неудачных входов до временной блокировки. |
| `ADMIN_LOGIN_WINDOW` | `15m` | Окно подсчёта попыток входа и длительность блокировки. |
| `API_RATE_LIMIT` | `120` | Число публичных изменяющих запросов от одного клиента за окно. |
| `API_RATE_WINDOW` | `1m` | Окно публичного rate limit. |
| `TRUST_PROXY_HEADERS` | `false` | Разрешает использовать первый адрес из `X-Forwarded-For` для rate limit. |
| `LLM_PROVIDER` | `mock` | Провайдер ответов: `mock` или `gemini`. |
| `LLM_API_KEYS` | пусто | Пул из 1–8 ключей Gemini через запятую. Имеет наивысший приоритет. |
| `LLM_API_KEY` | пусто | Один ключ Gemini для обратной совместимости. |
| `GEMINI_API_KEY` | пусто | Альтернативное имя одного ключа. |
| `GOOGLE_API_KEY` | пусто | Последний резервный источник одного ключа. |
| `LLM_MODEL` | `gemini-2.5-flash` | Модель Gemini REST API. |
| `LLM_TIMEOUT_SECONDS` | `15` | Таймаут одного HTTP-запроса к Gemini. |
| `ARENA_MODEL_URL` | пусто | URL локальной PyTorch модели намерений. Compose задаёт `http://model:8090`. |
| `ARENA_MODEL_TIMEOUT_SECONDS` | `2` | Таймаут запроса к ArenaLM. |
| `ARENA_MODEL_MIN_CONFIDENCE` | `0.55` | Минимальная уверенность ArenaLM от 0 до 1. |
| `LOG_LEVEL` | `info` | Минимальный уровень JSON-журналов: `debug`, `info`, `warn`/`warning`, `error`. |

Неположительные или некорректные значения длительностей и числовых лимитов
заменяются безопасными значениями по умолчанию.

## Production-проверки

При `APP_ENV=production` сервер завершает запуск с ошибкой, если:

- не задан `DATABASE_URL`;
- `ADMIN_PASSWORD` равен `change-me`;
- пароль администратора короче 12 символов.

Для production рекомендуется:

```dotenv
APP_ENV=production
DATABASE_URL=postgres://...
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=длинный-уникальный-пароль
TRUST_PROXY_HEADERS=true
LOG_LEVEL=info
```

`TRUST_PROXY_HEADERS=true` следует включать только за доверенным reverse proxy,
который сам формирует или очищает `X-Forwarded-For`. В локальном Compose это
значение должно оставаться `false`.

## Выбор ключей Gemini

Порядок выбора конфигурации:

1. непустой список `LLM_API_KEYS`;
2. `LLM_API_KEY`;
3. `GEMINI_API_KEY`;
4. `GOOGLE_API_KEY`.

Пробелы вокруг ключей удаляются, пустые и повторяющиеся значения
отбрасываются. Больше восьми уникальных ключей считается ошибкой конфигурации.
В журналах выводится только число настроенных ключей.

Ротация работает циклически и безопасна для параллельных запросов:

- `401` и `403` исключают ключ минимум на пять минут;
- `429` исключает ключ на время из `Retry-After`, а без заголовка — на минуту;
- `500` и `503` повторяются один раз с задержкой из `Retry-After` или 200 мс;
- после исчерпания доступных ключей используется локальный анализатор и
  детерминированная реплика.

Один пользовательский ход может вызвать Gemini дважды: сначала для
классификации свободного текста, затем для переформулирования выбранной
движком реплики.

При заданном `ARENA_MODEL_URL` очевидные действия сначала распознаются строгими
локальными правилами, остальные реплики передаются ArenaLM. Gemini или
локальный анализатор остаются fallback. Игровые показатели вычисляются только
backend независимо от выбранного классификатора.

## Публичный rate limit

Лимит применяется к `POST`, `PUT` и `DELETE` под `/api/v1/`, кроме маршрутов
`/api/v1/admin/`. Административный вход имеет отдельный лимит попыток.

Ответы публичного лимитера содержат:

- `X-RateLimit-Limit`;
- `X-RateLimit-Remaining`;
- `Retry-After` при ответе `429 Too Many Requests`.

Чтение данных и health endpoints не расходуют лимит.
