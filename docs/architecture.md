# Архитектура

Проект реализован как модульный монолит.

```text
Пользователь / Администратор
            ↓
        Vue 3 SPA
            ↓
       Go HTTP API
       ↙         ↘
PostgreSQL    Negotiation Engine
                    ↓
             AI Provider / Mock
```

## Frontend

Vue отвечает за интерфейс игрока и администратора. Состояние переговорной
сессии хранится в Pinia. Повторяемая логика выносится в composables, HTTP-вызовы
изолированы в `src/api`.

## Backend

- `httpapi` — HTTP-маршруты и middleware;
- `adminauth` — хеширование пароля и управление административными сессиями;
- `negotiation` — бизнес-логика и оценка реплик;
- `repository` — хранение сценариев и сессий;
- `llm` — абстракция AI-провайдера;
- `database` — подключение к PostgreSQL;
- `webapp` — встроенная production-сборка Vue.

## Надёжность AI

Сценарный движок работает без внешней модели. AI улучшает анализ текста и
формулировки ответов, но при ошибке используется `MockProvider`.

## Правила сценария и состояние сессии

У сценария есть сохранённые в PostgreSQL правила: лимит ходов, порог доверия,
необходимые действия и ограничения предложения собеседника. У сессии есть
отдельное состояние этапа переговоров и выполненных действий. Миграция
`00002` заполняет правила существующих демонстрационных сценариев; при первом
запуске на пустой БД эти правила задаёт `SeedDefaults()`.

Каждый ход получает объяснимый разбор: распознанную технику, изменения доверия,
аргументации и давления, сильные стороны, риски и рекомендацию. Разбор
возвращается вместе с ответом и сохраняется как JSONB в `messages.analysis` у
реплики игрока.

При завершении сессии движок читает сохранённые разборы и формирует сводку:
частоту техник, повторяющиеся риски, приоритетные рекомендации и лучший ход.
Сводка сохраняется в `results.analysis`, поэтому результат после перезапуска
сервера совпадает с результатом, полученным при завершении переговоров.

Первая реплика копируется в сессию при её создании. Поэтому последующее
редактирование сценария не изменяет историю уже начатых переговоров.

Публичный список сценариев не возвращает правила и цель собеседника. Файлы в
`scenarios/` служат примерами данных: сервер сейчас заполняет демонстрационные
сценарии в `SeedDefaults()`. Движок применяет правила к проверке ходов,
изменению состояния переговоров и итоговой оценке.

Структурированный движок поддерживает Гарвардский метод, четыре этапа SPIN и
подготовку BATNA. Прогресс SPIN и факт определения BATNA хранятся во флагах
`SessionState` внутри JSONB `negotiation_sessions.state`; поле `spinStage`
фиксирует последний последовательно завершённый этап. Старые записи остаются
совместимыми: отсутствующие флаги читаются как `false`. Нарушение порядка SPIN
не блокирует ход, но уменьшает его влияние и отражается в объяснимом разборе.

Административный API возвращает полную модель сценария и позволяет создавать,
изменять и удалять сценарии. Изменение блокируется при активных переговорах.
Удаление блокируется при наличии любой связанной сессии, поэтому история и
результаты переговоров не теряют ссылку на исходный сценарий.

## Production

Vue собирается на первом этапе Dockerfile. Результат встраивается в Go-бинарник.
В production запускается один контейнер и управляемая PostgreSQL.

## Авторизация администратора

При запуске пароль администратора из окружения хешируется bcrypt и сохраняется
в PostgreSQL. После входа сервер выдаёт случайный токен с ограниченным сроком
действия. В базе хранится только SHA-256 hash токена. Смена настроенного пароля
и `POST /api/v1/admin/logout` отзывают активные сессии. Просроченные записи
удаляются при запуске и успешном входе. Число попыток входа ограничено временным
окном.

HTTP слой добавляет Content Security Policy, запрет встраивания страницы,
запрет MIME sniffing, ограничение browser permissions и строгую referrer policy.
